Investigation details and an evolution graph of runtime.
* Investigation
Runtime scaled superlinearly in the baseline, I didn't push it past 500 on initial tests out of fear.

Looking at the functions and flamegraph, there's two main computations for us to deal with:
- =stabilize=, which can be vectorized/parallelized
- =find_identity=, which *should* be vectorized, which we need to confirm.
  
Right now the algorithm implements a scatter pattern which can have performance issues. We can change this to be a /gather/ instead.
  
AVX 512 supports byte/word instructions, and the values in these arrays are guaranteed to be less than 16. So we should be able to get speedups by changing the =int= type to =int8_t= and auto-vectorizing. Pre-topple, the values are at most 7. So we can do a really cheap test to generate "change" masks with AVX512 =VPTESTM=. Furthermore, you can apparently use write-masks with AVX-512 to do add/sub?
